Research notes

How this benchmark works

Each swarm-shooter build below was produced in a fresh one-shot session — one per model per run, with no prior conversation context. The session receives only the prompt, a fixed interface contract (Godot 4.7.2, a fully self-contained scene, 1152×648), and, in Run 2, its own previous code. Effort settings were held constant across both runs: Luna at max, Sol at low, Opus 5.5 at low. Integration — navigator registration, the web export, publishing — is done by the producer and is not part of the measured build time. Wall time runs from session created (spec sent) to completion; token counts are the gateway's session usage figures.

The prompts, verbatim

Run 1 — every model, identical

“Build a 3D swarm-shooter demo in Godot 4.7: a player ship at the bottom of the screen that shoots, with effects, controlled with the arrow keys, and a few enemies. Just a demo.”

Run 2 — each model reviewed its own Run 1 code

“Review your code. Polish it, add visual features or improve visual features, and check for bugs.”

How the costs are estimated

Estimated cost = input tokens × input price + output tokens × output price, at the vendor's official API list price for the model:

  • These are API-equivalent estimates, not bills. The builds ran on subscription quota pools; no per-token invoice exists. The estimates answer "what would this have cost on the API?" and nothing more.
  • Caching is ignored. The gateway's token counts do not separate cache reads or writes, so every token is charged at the full rate.
  • Opus reports no usable input/output split (total tokens only), so its costs are shown as a range: all tokens at the input rate, up to all tokens at the output rate.
  • Luna's Run 1 token total was flagged stale by the gateway; its Run 1 figures are approximate.

The Luna defect

Luna's Run 1 build shipped with a typed-array script error in its mesh builder: the polygon function rejects the untyped arrays its own call sites pass, so the enemy meshes never build and no enemies render. The build is published exactly as submitted — "As submitted: script error — enemies don't render" is noted on its card in the navigator. And the Run 2 follow-up did not rescue it: Run 2 did not fix the Run 1 mesh bug. The same errors fire in the Run 2 build, and its formation still never appears on screen.
